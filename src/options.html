02

Advanced URL Rules

First enabled matching rule wins. Rules override your allowlist while blocking is on.

Matching tips
  • AND joins conditions that must all match. OR starts another matching group.
  • Match on host, path, or query. Host ignores case and keeps www.
  • Path and query preserve case and URL encoding. Query excludes the leading ?.
  • Wildcard matches the whole value: * means zero or more characters. Other operators treat * literally.
  • Rules apply on document loads, not same-document navigation.
  • The whole list is validated before saving. Errors leave saved rules unchanged.

Prevent removal with managed browser policies

You can use root privileges to apply managed browser policies so you cannot disable or remove the extension through browser controls. To further prevent undoing these policies, require a YubiKey for root access and store it inside a key lock box.

Copy the JSON below into managed_policies.json in your browser's managed policy folder. The location varies by operating system and browser; search for your browser/os managed policies folder location.

{
  "ExtensionSettings": {
    "xxxxxx": {
      "installation_mode": "force_installed",
      "update_url": "https://clients2.google.com/service/update2/crx",
      "override_update_url": true
    }
  },
  "MandatoryExtensionsForIncognitoNavigation": [
    "xxxxxx"
  ],
  "BrowserAddPersonEnabled": false,
  "BrowserGuestModeEnabled": false
}

Note: Replace every xxxxxx placeholder with your extension ID from Manage extensions → SinBlocker → ID.

For Brave, add "IncognitoModeAvailability": 1, before "BrowserAddPersonEnabled" in the JSON above to disable private browsing while MandatoryExtensionsForIncognitoNavigation is not yet available in Brave.
